2.2 布局维度

导航结构层级对比

灵基：顶部工具导航 + 中部项目分组（灰色标签）+ 会话列表 + 底部配置。导航结构清晰，但项目与会话的视觉层级区分度偏弱。

Codex：顶部功能入口 + 置顶区 + 项目分组（加粗标题）+ 会话列表（缩进），层级关系清晰，视觉权重分配合理。

WorkBuddy：顶部搜索 + Logo区 + 功能导航区（含二级展开）+ 任务列表 + 底部账户，层级最丰富，适合复杂操作场景。

Claude Code：顶部模式切换（标签在侧边栏内）+ 功能入口 + 置顶区（带引导文案）+ 项目-会话列表 + 底部账户。模式切换与侧边栏高度整合。

空间利用率对比

灵基：宽度约185px，在8款产品中最窄，会话和项目名称文字截断风险高。无折叠选项，内容区永久压缩。

扣子编程 & 飞书妙搭：提供「展开+收起」两档，用户可根据任务需要自主选择空间占比，对内容区友好。

秒悟：以极紧凑的65px图标栏为主，悬停时展开历史面板，最大化内容区而不牺牲导航可达性。

Qoderwork：唯一支持连续拖拽调整的产品，兼顾个人偏好差异，适应不同工作流。

顶部区域策略对比

灵基：模式切换（对话/工作/开发）位于顶部中央 topbar，不在侧边栏内，导致两者分离，用户在模式切换时视线需要跨越到页面中心。

Claude Code：模式切换标签（Chat/Cowork/Code）集成在侧边栏顶部，用户操作路径短，上下文连贯。

WorkBuddy：Logo + 版本号 + 状态指示在最顶部，功能导航紧随其后，品牌感强。

底部区域策略对比

灵基：仅有「配置管理」一个底部入口，缺少用户账户信息，与竞品相比显得单薄。

WorkBuddy：底部有头像 + 用户名 + 展开箭头，用户归属感强，账户操作入口清晰。

Claude Code：底部显示用户头像缩写 + 姓名 + 订阅级别（Pro）+ 设置图标，信息密度适中，层次完整。

扣子编程：底部显示用户积分 + 头像 + 关注者信息，将社交数据整合到导航，增强用户粘性。

3各产品左侧导航深度分析

灵

灵基 Lingji（分析主体）

约185px 固定宽度 10张截图 无折叠态 无搜索 无用户区

结构解析：灵基侧边栏分为三个区域：顶部固定工具（新会话 / 技能开发 / 灵基智能体开发 / 应用开发）、中部项目-会话列表（项目名作为灰色分组标签，会话项以圆点缩进排列）、底部配置管理。模式切换（对话/工作/开发）位于页面顶部中央栏，与侧边栏分离。

上下文菜单：项目右键提供「打开文件夹、编辑名称、删除」；会话右键提供「置顶、重命名、移动到项目（含二级子菜单）、删除」。功能本身覆盖基础需求，但所有操作均依赖右键触发，不支持悬停快捷操作。

分组功能：侧边栏标题区提供分组下拉（依据：Project / Date / None；项目筛选；技能筛选），功能有意义，但入口不够显眼，新用户难以发现。

已置顶标识：置顶后会话出现「已置顶」文字分区，样式为灰色小标签，视觉强调不足，缺乏图钉图标等直观标识。

推测未在截图中显示的状态（标注为红色标记）： 侧边栏折叠态 推测、 空状态（无会话时）推测、 Hover 快捷操作显示态 推测、 会话重命名内联编辑态 推测、 用户账户/设置交互态 推测
C

Codex（OpenAI 编程 Agent）

约220px 固定宽度 8张截图 有搜索 有过滤 有归档

结构优势：顶部四个功能入口（快速对话 / 搜索 / 插件 / 自动化）直接暴露核心能力；项目分组标题加粗且有展开/收起控件；会话项展示相对时间戳；置顶区与项目区有清晰视觉分隔。

过滤功能：提供整理方式（接项目 / 接期项目 / 按时间顺序 / 最近更新）、排序条件、显示范围（所有对话 / 相关）的下拉面板，帮助用户在大量会话中快速定位。

丰富的上下文菜单：会话右键提供「直接对话、新对话、归档对话、重命名、复制工作目录、复制会话ID、消去本地/到工作树、在当前窗口打开」共9项，覆盖开发场景的高级需求。项目右键提供「固定项目、创建永久工作树、归档对话、移植」等开发者友好操作。

推测未显示状态 推测：侧边栏完全展开/收起态、会话重命名内联编辑态、搜索结果态、空状态。
W

WorkBuddy

约300px 固定宽度 5张截图 有搜索 有状态可视化 有用户区

最丰富的功能导航：WorkBuddy 侧边栏涵盖 Claw（AI对话）/ 专家 / 技能 / 探索 / 连接器 / 资料库（含腾讯文档等子项）/ 自动化 共7大功能区，以图标+文字标签形式呈现，产品能力透明度最高。

任务状态可视化：任务进行中时，侧边栏会话项附近显示运行指示器；置顶任务使用橙色图钉图标标注，视觉识别度最高，是所有竞品中置顶标识最直观的设计。

底部账户区：底部显示用户头像+名称+展开箭头，归属感强，且右箭头暗示有更多账户操作可供展开。

推测未显示状态 推测：导航项 Hover 态、连接器详细列表、资料库展开态、多任务并发时的状态显示、侧边栏无任务时的空状态引导。
CC

Claude Code（Cowork Mode）

约285px 固定宽度 4张截图 模式切换内置于侧边栏 六维度过滤 有用户区

模式切换整合：Chat / Cowork / Code 三个模式以标签形式嵌入侧边栏顶部，用户不需要移动视线到页面中央即可切换工作模式，与灵基的分离式设计形成明显对比。

置顶引导设计：Pinned 区域在无置顶内容时显示「Drag to pin」的引导文字，教育用户交互方式的同时保持区域占位，避免界面坍缩。

最强大的过滤系统：支持按 Status（Active/All）/ Project / Environment / Last Activity / Group by / Sort by 六个维度过滤会话，适合同时管理大量并发任务的专业用户。

底部账户区：头像缩写 + 用户名 + 订阅等级（Pro）+ 设置图标，信息层次完整，设计克制。

推测未显示状态 推测：侧边栏折叠态（若有）、Routines详细列表、Customize设置页、会话重命名内联编辑、More菜单展开内容。
扣/飞

扣子编程 & 飞书妙搭（折叠态对比）

扣子约240/46px · 飞书约138/46px 占位式折叠 各2张截图

占位式折叠（Placeholder Collapse）：两者均采用「收起后以图标占位」的策略，而非完全隐藏侧边栏。收起态保留一个窄栏（约46px），每个导航项仍以图标显示，用户不会因折叠而失去导航上下文。这是目前业界最常见的侧边栏收起策略之一。

扣子编程亮点：展开态提供「新建项目」和「导入项目」两个快捷操作按钮，将最高频操作前置；底部显示用户积分（3000分）和关注/被关注数，强化社区氛围。

飞书妙搭亮点：扁平化的导航结构，仅有5个一级入口（新应用/导入/我的应用/市场/开发者社区），配合底部次级设置入口，认知负担最低。

两者均未展示 推测：Hover状态、点击收起按钮的动画过渡、收起态时Tooltip的展示方式、移动端适配。
秒/Q

秒悟 & Qoderwork（特殊折叠策略）

秒悟约65px常驻 / Qoderwork约268px可调 最灵活的布局方案 各2张截图

秒悟·悬浮展开策略：常驻65px宽图标轨道，悬停「历史」图标时在轨道右侧弹出覆盖式历史面板（约320px），面板不占用固定布局空间。这是「Flyout/Overlay」交互模式，适合内容区优先的产品，但弹出内容需注意不遮挡当前操作区域。

Qoderwork·最灵活方案：默认约268px宽，支持拖拽调整（有最小和最大宽度限制），同时提供「完全关闭」按钮将侧边栏隐藏。这是功能最完整的布局控制方案，适合专业用户，但实现成本相对较高。关闭态下，侧边栏完全消失，内容区可获得最大空间。

推测未显示状态 推测：秒悟·历史列表有内容时的态、Qoderwork最小/最大宽度边界态、Qoderwork拖拽过程中的视觉反馈。

4灵基左侧导航现存问题

基于截图分析与竞品对比，以下为灵基左侧导航存在的主要设计问题，按优先级排序：

1

缺乏侧边栏折叠能力，内容区永久压缩 高优先级

灵基侧边栏约185px宽度始终占据屏幕空间，无法折叠。当用户专注于内容创作或代码审查时，固定的侧边栏侵占了宝贵的工作区域。在所有8款竞品中，扣子编程、飞书妙搭、秒悟、Qoderwork均提供了折叠能力。

参考：扣子编程（占位式）/ 秒悟（悬浮式）/ Qoderwork（完全关闭）
2

模式切换与侧边栏分离，操作路径割裂 高优先级

「对话/工作/开发」的切换器位于页面顶部中央 Topbar，而会话、项目的管理在左侧侧边栏。用户需要在两个不同的空间区域之间跳跃视线，违反了导航操作在空间上应集中的原则。Claude Code 将 Chat/Cowork/Code 的切换集成进侧边栏顶部，实现了更连贯的操作流。

参考：Claude Code（顶部标签整合于侧边栏内）
3

缺乏会话/项目搜索功能，大量内容难以导航 高优先级

侧边栏内没有任何搜索框或快捷检索入口。随着会话数量增长（如截图中已出现多个项目 Figma project / Lingee / workspace + 数十条会话），用户将无法快速定位目标会话，只能通过滚动浏览。Codex 在顶部提供专用「搜索」入口，WorkBuddy 有任务搜索栏。

参考：Codex（顶部搜索入口）/ WorkBuddy（搜索栏）
4

项目与会话的视觉层级区分度弱 高优先级

项目名称（Figma project / Lingee / workspace）以小号灰色文字标签呈现，与会话项的视觉差异不足。用户扫视时难以快速区分「这是项目分组」还是「这是另一条会话」。Codex 使用加粗标题 + 明显的展开/收起控件区分项目层级，视觉层次清晰度显著优于灵基。

参考：Codex（加粗项目标题 + 缩进会话列表）
5

侧边栏宽度约185px偏窄，文本截断风险高 中优先级

185px在8款产品中最窄，项目名「灵基智能体开发」、会话标题「构建费用报销单」等长文本在此宽度下极易被截断，影响用户识别。竞品普遍在220px～300px之间，且Qoderwork支持自由调宽，灵基在这一维度处于劣势。

参考：Qoderwork（可拖拽调宽）/ WorkBuddy（300px宽裕空间）
6

缺少用户账户信息区域，归属感弱 中优先级

侧边栏底部仅有「配置管理」一个功能入口，无用户头像、姓名、账户等级等信息。对比 WorkBuddy、Claude Code、扣子编程均在底部提供完整的用户区，灵基侧边栏显得过于工具化，缺乏用户归属感，也不利于账户相关功能（切换账户、查看订阅等）的入口设计。

参考：WorkBuddy（头像+姓名+展开）/ Claude Code（缩写+等级+设置）
7

会话状态无可视化标识，运行中任务难以感知 中优先级

在会话状态截图中，可以看到「进行中 技能1·已探索5」等运行信息出现在内容区，但侧边栏对应会话项没有任何状态指示（如动态图标、颜色标记等）。当用户切换到其他会话时，无法在侧边栏感知到有任务正在后台运行。WorkBuddy 和 Qoderwork 均为此提供了状态指示器。

参考：WorkBuddy（运行中动态标识）/ Qoderwork（任务监控面板）
8

置顶标识视觉强调不足 中优先级

置顶会话通过「已置顶」灰色文字分区标签展示，缺乏图标化的视觉强调。与 WorkBuddy 的橙色图钉图标相比，灵基的置顶标识在快速扫视时不够突出，用户需要仔细阅读才能意识到某会话已被置顶。

参考：WorkBuddy（橙色图钉图标）/ Claude Code（Pinned区+拖拽置顶引导）
9

添加项目依赖系统文件浏览器，交互割裂感强 中优先级

添加项目时弹出操作系统原生文件选择器，这一交互与产品整体 UI 风格不一致，且无法在产品内完成创建流程（如直接新建命名项目）。Codex 和 WorkBuddy 均提供了产品内的项目创建/命名流程，体验更一致。

参考：Codex（产品内创建项目 + 永久工作树）
10

所有操作仅通过右键触发，Hover 态交互缺失 低优先级

从截图分析，灵基会话和项目的快捷操作（重命名、删除、移动等）均需要通过右键菜单触发，未见鼠标悬停时的内联操作按钮（如「···」更多菜单）。Codex 和 Claude Code 在会话项 Hover 时会显示操作图标，提供更直接的操作路径，减少用户的学习成本。

参考：Codex / Claude Code（Hover 显示操作入口）

5灵基左侧导航优化机会点

基于以上问题分析，结合竞品最佳实践，提出以下具体优化方向：

O1

引入侧边栏折叠能力（推荐采用「占位式」策略）

建议在侧边栏顶部或边缘增加收折触发按钮，收起后以约46px宽的图标轨道占位（参考扣子编程/飞书妙搭），保留图标导航能力。不建议采用「完全隐藏」方案，因为工具入口的常驻可见性对 AI 产品的操作流畅性很重要。可进一步评估「悬浮展开」（秒悟模式）是否适合灵基的使用场景。

参考借鉴：扣子编程 / 飞书妙搭（占位式）/ 秒悟（悬浮式）
O2

将模式切换整合进侧边栏，减少视线跳跃

将「对话/工作/开发」切换器从顶部 Topbar 下移到侧边栏顶部，以标签（Tab）或胶囊按钮形式呈现。这样用户的导航操作（切换模式 + 选择会话 + 管理项目）都集中在左侧，提升操作连贯性。需要注意的是，当前 Topbar 中间位置可以空出，用于展示当前会话标题等上下文信息。

参考借鉴：Claude Code（Chat/Cowork/Code 标签集成于侧边栏顶部）
O3

增加会话搜索/快速跳转入口

在侧边栏顶部工具区域增加搜索入口（可以是全局搜索的触发按钮，或专用于会话/项目检索的搜索框）。建议支持按会话标题、项目名、会话内容关键词搜索，并提供快捷键触发（如 Cmd+K）。短期可参考 Codex 的独立搜索图标入口，中长期可升级为类 Spotlight 的全局搜索体验。

参考借鉴：Codex（搜索入口）/ WorkBuddy（任务搜索框）
O4

优化项目-会话视觉层级，增强扫视识别度

将项目分组标题由灰色小字提升为加粗标题（同时保留展开/收起的 chevron 图标），会话项在项目下方适当缩进，使树状层级关系一目了然。同时考虑在项目标题区加入「＋新会话」的快捷操作，减少用户在不同区域之间跳转的操作步骤。

参考借鉴：Codex（加粗项目标题 + 缩进会话列表）
O5

完善底部用户账户区

在「配置管理」上方或替换「配置管理」，添加用户头像（缩写或实际头像）+ 用户名 + 账户等级（如 Pro / Team）的标准账户区域。点击可弹出账户管理菜单（登出、切换账户、查看订阅等）。「配置管理」的功能可整合为账户区点击后的二级菜单项，或移动至图标按钮形式。

参考借鉴：Claude Code（缩写+姓名+等级+设置）/ WorkBuddy（头像+姓名）
O6

为运行中的会话/任务添加侧边栏状态指示

当某个会话有 Agent 任务正在运行时，在侧边栏对应会话项上显示状态标记（如旋转动效小点、彩色进度条、「运行中」文字标签等）。这可以让用户在多任务切换时，无需进入会话即可了解各任务状态，是 AI 异步任务场景中不可缺少的设计。

参考借鉴：WorkBuddy（任务进行中动态标识）/ Qoderwork（任务监控）
O7

引入 Hover 快捷操作，降低右键依赖

在会话项和项目标题 Hover 时，显示「···」更多操作按钮（或直接展示 2-3 个最常用操作的图标），让用户无需右键即可触发重命名、删除、移动等操作。对于不熟悉右键操作的用户（尤其触控板用户），这可以显著降低功能发现难度。同时，Hover 时对整行进行浅色高亮，强化可交互性感知。

参考借鉴：Codex / Claude Code（Hover 显示操作入口）
O8

升级置顶标识为图标化设计，并支持拖拽置顶

将「已置顶」文字分区标签升级为图钉图标（填充式，以橙色或品牌蓝区分），使置顶状态在快速扫视时一目了然。进一步可参考 Claude Code 的「Drag to pin」设计，支持拖拽方式置顶会话，提升交互灵活性同时兼具操作教育功能。

参考借鉴：WorkBuddy（橙色图钉图标）/ Claude Code（拖拽置顶+引导文案）
